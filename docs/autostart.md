# Windows 开机启动

设置中的开机启动选项在保存后生效。状态来自当前用户的实际注册结果，不使用配置文件中的布尔值。

- 只操作 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `NekoriEmojy` 值，无需管理员权限。
- 同时读取当前用户 `Explorer\StartupApproved\Run` 和 `Run32` 中同名记录。系统禁用时，开关显示关闭；只有用户主动开启并保存，才清除 Nekori 自身的已知禁用记录。不会修改其它应用或自动解除系统禁用。
- 登录启动传入 `--autostart`，托盘可用时保持面板隐藏；无托盘时显示主面板，避免无法访问。手动启动不受影响。
- 源码使用当前 Python 环境，优先同目录的 `pythonw.exe`，并传入绝对 `main.py` 路径。移动环境后需主动重新启用。
- 发布包通过 Nekori 的版本信息和协议 1 清单定位公开启动器。现有轻量包入口是根目录 `SuzuEmojy.exe`；独立包入口转交 `bin/SuzuEmojy.exe`，这些文件名属于已有更新协议，不代表产品或注册项仍叫 Suzu。两种启动器都完整转交启动参数。
- 编译模式以 `GetModuleFileNameW` 获取真实进程路径，不依赖 Nuitka 的 Python 占位路径。
- 启动时只修复能够精确匹配当前安装目录的旧 Python / 核心入口命令；不会认领其它目录、其它应用或不确定的记录，也不会顺带解除 Windows 禁用。普通源码启动不自动修复。

保存遇到注册表拒绝时，显示失败并重新读取实际开关状态，不重复写入同一失败值；其它已保存设置及本轮其它待保存修改保留。配置写盘失败时只对已经成功执行的系统操作尝试一次回退，回退失败也会明确提示，不把开关显示为虚假的成功。

针对性测试覆盖模拟拒绝、路径变化、编译路径和保存回退；`tests/test_autostart_windows.py` 使用隔离的非启动注册表子键验证真实 Windows 读写、系统禁用与其它应用记录保留，不修改真实 Run 启动项。发布包参数和实际启动入口另行验证。上述测试不替代真实 Windows 注销／登录验收。

进程路径及系统禁用处理参考 [SuzuEmojy v1.13.1 的修复 dc14f4a1f5](https://github.com/IxinorTyan/SuzuEmojy/commit/dc14f4a1f5)。涉及实质性实现的来源已在源码标注，沿用项目 GPL-3.0 许可；未引入整套上游设置界面或目录结构。
