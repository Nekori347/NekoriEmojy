## 架构与上游更新价值

数据模型、分类标签、图库与 UI 架构已明显独立演化，包括权威库索引、稳定资源 ID、递归节点和独立窗口／设置体系；媒体处理、交换包、去重、部分 Windows 集成及更新服务仍有实质继承。Nekori 已形成独立核心架构，同时仍是保留大量上游实现的衍生项目。Suzu 迁移及格式兼容是主动保留的产品能力，不能据此认定主体架构仍依赖 Suzu。

- [dc14f4a：v1.13.1](https://github.com/IxinorTyan/SuzuEmojy/commit/dc14f4a)：Nekori 已有视口虚拟化、卡片复用及限流解码；自启动修复已明确借鉴该提交，不重复移植。滚动期间暂停卡片创建／解码、停稳恢复的调度方案可以参考，需适配当前混合布局，成本中。自动粘贴中的剪贴板序列、修饰键和超时校验值得关注，成本中。
- [c94058e：粘贴](https://github.com/IxinorTyan/SuzuEmojy/commit/c94058e)：自身异步剪贴板通知误取消粘贴的具体连接方式未用于 Nekori，不直接套补丁；外部剪贴板替换的序列验证，以及普通前台切换失败后临时连接输入队列、随即断开的焦点恢复方案值得参考，成本中。

以上为静态源码适用性判断，不代表已运行验证相关粘贴行为或性能收益。

## 维护原则

低频关注上游，选择性借鉴有效修复，不整体同步。优先关注剪贴板／焦点恢复、Windows 自启动与更新、媒体格式、QQ／Telegram 和交换兼容；图库性能方案按 Nekori 现有架构评估。已覆盖能力不重复移植。保留完整 Fork 历史、Suzu 兼容能力、许可证及来源说明；不建立自动同步机制，不据此清除历史或兼容代码。
