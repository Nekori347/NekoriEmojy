## T-07 / #35 / 168289e

保留44d7208的Python sys/thread异常链、无资源内容的类型/帧留痕及faulthandler。增加：

- 设置→关于→诊断资料：“查看日志”打开当前应用diagnostics目录；“导出诊断资料…”由用户选择ZIP目标。
- 导出只读允许的exceptions.log/.1/.2和最多两份fatal日志，每份最多512KiB；版本、Python/Qt/OS/架构元数据。无Library遍历、不打包图片、配置、环境变量、命令行或凭据。过滤绝对目录、QQ账号数字、URL及常见令牌/认证字段；不自动上传。导出采用既有安全临时ZIP与完成后替换，成功、失败、取消分别反馈，旧目标在失败/取消时保留。
- 任务错误/部分成功转换补一次关联留痕，任务ID哈希、kind、受限阶段枚举及完成/总计数；不记录进度中的文件名/详情。ExchangeWorker被捕获的异常记录类型和代码帧，取消不当作错误。不是所有已被各模块自行处理的异常都会被全局捕获。

### 确实有界的保留策略

原RotatingFileHandler只按普通消息预计长度轮转，大记录可超过上限；原faulthandler直写文件也不能靠文件数保证单文件上限。

- 现在Python异常日志单条最多16KiB，每文件512KiB、最多3份，按UTF-8字节（含换行余量）决定轮转。
- 原生输出经匿名管道交给独立的小型写入进程，每文件最多512KiB，超限继续排空而不落盘；独立于崩溃解释器的GIL，避免管道写满阻塞故障转储。此进程只阻塞读取诊断管道，不初始化Qt、Library、更新检查或单实例管理；正常关闭/父进程死亡后EOF退出，无轮询或恢复逻辑。源运行通过services.crash_evidence入口，冻结运行预留同一main的--diagnostic-writer早期分支。
- 保留上一份原生记录与当前记录共最多2份，启动时处理旧版本过大记录。五份受管理日志硬预算为2.5MiB；正常无原生输出则清掉空文件。用户主动导出的ZIP不属于自动日志轮转，不自动删除。
