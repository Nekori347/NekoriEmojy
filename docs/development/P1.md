# P1：独立资源库与最小诊断

实施分支 `codex/p1-library`，基于已推送的 P0 提交。当前是开发版本，尚非完整 NekoriEmojy 成品；P2～P6 的功能和原生交互验收不能从本记录推断通过。

## 结构与数据边界

选择一个程序目录树之外的库根目录。`nekori-library.json` 只标识格式与稳定库 ID；`data/` 保留上游的 images/inbox/cache 和五个业务 DB，新增 `library.db` 管理业务偏好、schema 迁移登记和迁入记录。日志、迁移报告和升级前快照也随库保存。资源引用为库内文件名，源盘符不是运行依赖。

轻量定位文件位于 `%LOCALAPPDATA%/NekoriEmojy/bootstrap.json`，只记最近库；可选开发环境变量 `NEKORI_BOOTSTRAP_DIR` 用于隔离测试。定位文件丢失可手选同一库。作者头像缓存与首次引导日志也在该可丢弃位置。Fluent 的派生主题缓存放在库的 cache 中，用户偏好以数据库为准。

缺失库、较新版本、必要数据表缺失、路径越界与第二个实例占用都拒绝连接。数据库的运行连接使用 `mode=rw`，不会把缺失 DB 自动建为空文件。只有明确新建库流程可使用 CREATE。正常启动不调用旧的原地迁移、全库 hash/去重或删除死链流程。

## 成熟组件与选择

没有新增运行时第三方依赖。继续使用 Python 3.12.14 / SQLite 3.53.1：SQLite rollback-journal、ATTACH 多库事务、内置 backup API 和 `PRAGMA user_version`。保留现有五表服务组织，避免为 P1 引入 ORM 后再迁移整套 UI；统一入口协调结构升级和 exchange 提交。

SQLite 官方说明多库事务需主库非内存库且不使用 WAL 才具备整组原子提交，因此本实现明确采用 DELETE journal。升级前在停写会话内用 SQLite backup 生成完整、可核验 DB 快照；schema 1→2 是新增迁入记录表，不清用户数据。注入升级异常时事务整体回滚，保留快照，可重试。任意旧 EXE 直接打开新 schema 不在回退承诺内。[SQLite ATTACH](https://www.sqlite.org/lang_attach.html)、[Backup API](https://www.sqlite.org/backup.html)、[原子提交说明](https://www.sqlite.org/atomiccommit.html)。

日志复用标准库 QueueHandler/QueueListener、512 条有界队列、单文件 1 MiB 加 3 个轮换文件。队列满时丢弃并计数；文件错误不递归记录。详细模式最长 10 分钟。以上是当前实现值，后续按 P2/P5/P6 实测调整，非用户硬阈值。[Python logging handlers](https://docs.python.org/3.12/library/logging.handlers.html)。

这些能力属于现有 Python 运行时，未增加包体组件；额外 CPU/内存/包体成本尚未完成综合性能测量，不能用标准库身份代替实测。

## 旧源与整库复制

旧 SuzuEmojy 必须先停止写入。读取源文件及哈希，复制 DB/WAL/JSON/资源，再比较源与副本；SQLite 只打开隔离检查副本，绝不在旧源执行迁移或删除 JSON。成功库内保留原始快照、映射、数量及跳过原因。失败阶段独立保留，目标不启用；重试目标必须为空，已完成的库应直接打开。

DB 与 JSON 分别统计 categories、relations、order、metadata、icons、recent。存在冲突时逐项选择 DB 或 JSON，即使 DB 为空也不自动覆盖 JSON。没有猜测历史分类；无法对应的引用有明确 missing/ambiguous 记录。所选来源未覆盖的原始字段仍在完整快照中，不能据此宣称它们都已变成可编辑新功能。

完整复制在会话维护期间停写，SQLite 数据采用一致性 backup，其他文件复制并 SHA-256 校验；成功后切换到新位置，源库始终保留。库切换等待当前任务结束并重新建立主面板与服务，旧 Storage/Config 对象持有固定上下文，已关闭会话拒绝晚到写入。库 ID 可随完整复制保留，会话 ID 独立，用于后续异步结果归属。

## 界面、交换与发布隔离

首次运行提供打开/新建，连接失败保留原位置说明。设置页新增当前库位置、创建/打开/重连、整库复制迁移、旧源只读迁入及本地诊断导出。长迁移在后台线程执行，维护期间暂停当前界面任务；P3 再完成独立设置窗口与统一预览/保存。

诊断包只含结构化日志、异常类型/调用位置、库 ID、版本/结构/数量摘要，不带原图片、完整 DB、剪贴板、私密 OCR 文本或本地完整库路径。旧源恢复报告和原始快照不会混入诊断包；导出不上传。

原 exchange v1 保留。接入统一库上下文与多 DB 原子事务后，注入导入失败会回滚所有 DB 并移除本次新文件；完成通知失败不会删除已提交文件。新增回归样本还核实并修复原导出 `list(str)` 逐字符拆分关键词，以及导入漏建已声明空分类的问题。v1 没有手工排序字段，仍不称其为整库备份。

构建脚本停止复制 data，并增加发布树检查，拒绝 DB、用户配置、缓存与编辑器文件，带入 GPL LICENSE。停止跟踪上游遗留的运行 JSON、pyc、交换文件和旧崩溃报告；原始版本仍可从 Git 历史恢复。本阶段尚未重新生成最终 NekoriEmojy ZIP。
