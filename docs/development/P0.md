## 构建参数与真实体积

执行原 `build_nuitka.py`，在调用 Nuitka 时显式增加 `--zig --jobs=4`。保留原 `-march=x86_64_v3`、standalone、PySide 插件、排除项、FFmpeg 和发布目录整理流程。默认 MinGW 下载停滞的尝试已停止，不将它写成编译错误；Zig 是实际成功的工具链。命令适配仅用于 P0，不是产品数据核心或最终发布构建器。

## 既有能力与新增证据

源码中存在且须保留：图库浏览/懒加载/预览、分类及编辑删除图标、分类顺序和全局顺序、Tag/关键词/搜索/筛选、多选及右键、Ctrl+V 和文件/目录导入、资源交换、最近记录、精确/相似去重、全局快捷键、快捷面板、托盘、窗口拖动缩放/置顶、主题/语言、QQ 提取、TG 贴纸、WebM 转换及收件箱等。列举不是删除其他原能力的许可。

本次核查对交接起点的补充：

1. `CategorySidebar` 已有双击“全部表情”切换网格的代码；P3 应复用和完善它。
2. 全部相关源码/配置搜索未找到开机自启实现；尚不宣称源码外的旧发布方式没有该能力。开机自启仍是明确需求，最终要补齐并实测。
3. 自建样本的空分类已写入 exchange catalog，但原导入没有创建它。这是受控样本复现，不证明真实用户包的关系何时丢失。
4. ExchangeImportService 需要应用先建 schema；绕开正常启动流程直接导入到空目录会缺表。P1 的库上下文适配须保留这个前置条件。
5. 除 data JSON 外，Git 还跟踪旧 `.pyc`、编辑器交换文件及历史 Nuitka 报告；发布隔离不能只看 `.gitignore`。
