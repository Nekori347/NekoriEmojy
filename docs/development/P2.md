# P2：复制导入、持久身份与已知问题

实施日期：2026-09-14。P1 基础 f2da24da625771c1d13f1071eb078ba349af10fb；上游审阅 [efc0103](UPSTREAM-efc0103.md)。状态是开发实现及下述验证通过；不代表最终发布/用户事故全部验收。

## 已实现

- SQLite schema 3 增加 resource_identity：稳定资源 ID、相对图片名、内容版本、file MD5、pixel MD5、sync key、尺寸、格式、动画、size/mtime_ns、算法版本与状态。file/pixel 不混用；像素相同但宽高不同不会误判同图。内容变化时内容版本递增并使旧感知哈希失效。
- 去重查询 SQLite 索引，只对候选做文件状态校验。首次导入不全库解码；重连/force_reload 不重建索引。旧 v2 的未知身份通过 SQL 生成缺项队列并在后台逐项补齐；显式旧源迁入过程中直接计算新身份。缺项期间不假称全库查重完整，不自动删除后发现的相似/重复资源。
- ImportPipeline 共用文件、MIME/HTML/URL、QImage 适配；Ctrl+V 与“粘贴导入”按钮共用入口。URL 获取在线程中执行，采用标准库 urllib/HTMLParser，按实际图片数据校验而不靠 URL 扩展名；HTTP(S)/data:image，128 MiB 上限、读取超时及总时限，不扩展成网页抓取器。
- 所有普通文件入口只读源文件。收件箱不删除/移动输入；DB 记录大小、mtime 和处理结果以防自动重复，源变化可再次导入；失败可从原文件手动重试。源移动/删除不影响已入库副本。GIF 保留原字节，多帧 WebP 保留原 WebP，单帧 GIF 继续按原规则归一化静态 PNG。
- 入库先完成规范化，再通过持久导入日志、同卷暂存/rename 和跨 DB 事务发布身份、metadata、排序和分类；强制进程终止后只恢复原库未完成操作。并发相同输入只产生一个副本；统计在提交后确认，通知失败不会撤销已提交结果。
- add_images_to_category 是共用批量关系接口，单张/批量右键与导入调用它或同一 SQL 核心。只增加指定关系，其他分类和物理文件保留。P3 接入多选拖放、高亮与新增折叠小分类。
- QQ/TG 原有获取和专用格式逻辑保留，最终复制保存和目标分类提交汇入同一 Storage 核心。exchange v1 清单校验/分类/排序语义保留，读写同一个持久身份索引，不全库重解码。
- 批量删除以持久日志保护文件暂移和跨 DB 删除；普通异常恢复副本及关系，提交后的清理失败可恢复处理。有效身份不靠删除后全库重扫修复。
- 正确解析 PySide VoidPtr 的 MSG；客户区 WM_SETCURSOR 根据当前位置 Qt 控件/override cursor 恢复，保留文本、链接和边缘委托。附带修正了原先被 message.contents 异常吞掉的电源/主题消息解析。
- 默认诊断记录导入次数、主线程标志、输入字节、规范化/提交耗时和结果；详细模式才记录受限频率 cursor 数值，不记录图片内容、HTML、完整 URL 或剪贴板原文。

## 证据与实际边界

[测试结果](evidence/p2-tests.json)：52 项通过，含原 23 项。新增覆盖复制与动画字节保留、magic、失败统计、2000 条持久索引重连首导、12 路并发同图、跨库晚到任务拒绝、文件替换、DB 失败回滚、真实子进程 os._exit(73) 后恢复、删除故障恢复、缺项补齐、v2 升级不读图、MIME 解析、exchange/普通导入互认、宽高冲突。

[实际主程序启动](evidence/p2-startup.json)：offscreen 启动连续切换两个隔离库，通过。热键/头像外部请求在探针中禁用。

[性能探针](evidence/p2-import-performance.json)，2000 张生成的 256×256 PNG，同一宿主/依赖：

| 指标 | P1 | P2 |
|---|---:|---:|
| 打开库/构造服务 | 13.43 ms | 11.96 ms |
| 第一次导入 | 2690.51 ms | 81.14 ms |
| 第一次整库 sync_key 解码 | 2000 | 0 |
| 第二次导入 | 15.26 ms | 78.71 ms |

P2 的额外持久日志/完整事务增加每次保存的固定成本，未通过省略持久性来追求最低耗时。异步重复导入 100 次，Qt 10 ms 心跳计数 528，最大间隔 21.89 ms。测试未清空 OS 磁盘缓存、不是用户真实 PNG/GIF 混合库，也不是最终 EXE 延迟结论。

[自然鼠标路径记录](evidence/p2-native-cursor.json)：Windows backend、首屏 96 DPI，边缘→内容/文本/链接、多种光标正常；未自然复现旧残留，第二轮底边 HTCLIENT 样本不算通过。[原生残留注入](evidence/p2-native-injection.json)：在测试窗口内显式设置横向残留，再经修复恢复 I-beam/hand/arrow 三项通过，边缘委托、最大化文本和恢复正常窗口通过。这证明恢复机制可用，不证明已定位用户环境事故根因；真实拖动/缩放、跨屏 DPI、睡眠唤醒和最终包留至 P6。

MIME 载荷用 Qt 合成测试，尚无实际 Chromium 拖拽录制。需在最终 UI 和包中完成 T09/T10。当前未知身份补齐时，导入先与已验证索引查重；尚未补齐资源可能暂存重复，不会自动合并/删除人工状态，P3 提供显式维护/检查入口。外部程序恶意保持 size/mtime 不变的内容改写不在自动 stat 校验保证内，显式重新校验可检测；程序管理的内容变更须递增版本。
