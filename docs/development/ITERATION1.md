## 必要修复

- 根目录 C# 启动器原先丢弃全部参数，包括开机启动/显式启动的 `--library`。真实 C# 接收器重现为 7 个输入参数、0 个收到；修复后中文、空格、空参数、引号和末尾反斜杠逐个保真。启动器与发布隔离的 4 项针对性测试通过。
- Zig 0.16 本地缓存可错误复用 `#embed` 常量对象：同一 C 文本、不同比特 payload，第二个程序错误输出第一个 payload。独立 local cache 后正确。Nuitka 4.2.1 的常量 C 源使用该机制；构建现在每次新建 local cache，保留 global/download cache。这是构建工具限制的针对性规避，不改变产品存储。本轮真实完整构建和实际 EXE 运行通过。
- 构建脚本固定采用已验证的 Zig / 4 jobs，统一编译日志 UTF-8，清理生成目录前检查真实路径在当前 checkout 内。
- README 和使用说明改为 NekoriEmojy；明确迁入、资源包、整库备份不同边界，关于页的项目/发布链接指向本 Fork，保留上游作者致谢。

## 过渡验证

`scripts/iteration1/transition_probe.py --work <新隔离目录>` 从固定上游 Git 对象提取原服务源码，在子进程中操作生成的旧图库，不访问实际安装的 Suzu 或用户 data。

实测 **21 项检查通过**：3 个 PNG/GIF、3 个分类（含空分类）、5 条多分类关系、自定义图片/分类顺序、Tag、最近和偏好只读迁入；源文件 SHA-256 前后不变；小分类不复制图片；整库复制与重新打开保留小分类/折叠/关系；两版资源包互通并幂等导入；原图片不变。

旧 v1 格式不带自定义排序、小分类、最近或设置；原 Suzu 基线导入器忽略空分类，原导出器可能将关键词拆字符。直接只读 data 迁入保留完整关键词。v1 仅支持旧 PNG/GIF 范围，跳过其他格式并记录；不是整库备份。不得声称任意新版 Suzu 格式都已兼容。
