## 可比较证据

同一 240 资源隔离样本：首张添加到分类约 25.0→22.5 ms；余下 239 张批量添加约 16933.2→152.5 ms；240 张跨分类移动约 40659.3→149.1 ms。修后目标 240、来源 0、其它复制关系 240，内容顺序复连后保持。此为本机脚本计时，不能直接外推正式 3518 项库。

252 资源跨操作对照：单纯排序 24.4 ms，新建分类 23.7 ms，删除一张 221.7 ms；不能据正式版多项卡顿推定同一个根因。图库界面 240 项隔离调用中，批量添加总计约 310 ms、批量移动约 303 ms，其中树与图库增量刷新仍各需数十毫秒。删除及真实大库其它写操作的独立瓶颈没有在本轮消除。

首次导入的去重索引构建在旧路径中对约 255 个已知文件逐个进行 SQLite 查询，约 1018 ms；改为直接使用受控 `images/` 目录后，独立构建约 96 ms。12 张导入的旧路径总计约 2075 ms，首张约 947 ms；修复前的这一总耗时和修后不同运行条件下的总耗时不能作为整体导入提速比例。导入每张资源、缩略图及结束时图库刷新仍有独立费用。

真实 `ImportQueue/QThread` 与图库的交错探针：10 张导入单独约 1570 ms，边导入边排序约 1761–1836 ms；排序动作约 87–153 ms，发生时后台线程仍在运行。10 张均保存，目标卡片前的顺序在导入后仍正确；20 ms 定时采样的最大主线程间隙约 216–274 ms，结束时图库增量刷新曾占约 168 ms。此为 Windows 本机 Qt offscreen 队列和真实后台线程，不是实体鼠标与屏幕流畅度结论。

定向回归：`test_library_baseline.py`、`test_virtual_gallery.py`、`test_relative_navigation.py` 在测试拆分前的合计 16 项通过；导入锚点场景移至独立的 `test_import_order.py` 后单项通过；分类图标可见卡片测试通过。`test_gallery_folder_drop.py::test_busy_import_does_not_create_categories` 的旧替身缺少 `content_scope_node`，在本轮独立运行中失败；该路径未改，未为修复本轮问题改造其测试替身。源码 diff whitespace 检查通过。
