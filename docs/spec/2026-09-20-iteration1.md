# 当前生效范围：第一可用版

来源：用户 2026-09-20 的“当前开发策略调整”。本记录优先于旧阶段记录中的一次性 P0–P6 交付安排。
完整交接仍作为项目事实、长期需求、架构约束和 Roadmap 参考，不再是当前一次必须全部完成的任务清单。

## 三项最高优先级

1. **独立资源库**：程序与用户数据分离；用户指定库位置；外部图片只复制，不移动、删除或改名原文件；分类、关系、排序及必要元数据随库保存；替换、更新、移动程序不会使图库丢失。
2. **小型分类**：软件内大分类包含用户自建、命名、添加内容的平铺可折叠小分类，不做多级菜单。图片只存一份。复用 SuzuEmojy 已正常工作的分类、普通 Tag、筛选、多选、最近记录、去重等模块，避免无必要重写。
3. **安全过渡**：SuzuEmojy 源数据只读迁入；保留原数据作为回退；尽可能转换图库、分类关系、自定义排序及可靠可转换信息；保留资源包导入导出，明确两版本的可交换数据及格式限制。

## 额外需求必须先建议、后确认

必须同时满足：对日常使用有明显价值、成本很低、与当前模块高度重合、无大型依赖或架构、不明显扩大回归范围、不延迟第一可用版。
即使判断简单，也只能先列为“建议顺带实现”，说明增加的修改范围和原因，得到确认后再做。
用户候选：资源库重新指定/迁移、必要迁移诊断与错误提示、成本确实低的设置配置导入导出。
这些能力已有先前授权的 P1/P3 实现；保留已完成部分，不借候选名义扩大范围。

## 明确延期

安装程序、自动更新、大规模 UI 重构、隐性 Tag、OCR、多语言 OCR、OCR 模型管理。
**尤其禁止提前实现 OCR。** OCR、隐性 Tag 及人工修正体系须在第一可用版稳定后，作为独立阶段重新评估需求、收益、体积、性能、成本，再决定是否实施。
已有 P4 隔离实验只存档于独立分支，不进入当前版本，不继续评估或接入。

## 验收与停止条件

现有 SuzuEmojy 用户能够保留原数据，将图库及可靠可迁组织信息导入 NekoriEmojy，指定独立资源库，完成日常导入、浏览、分类、搜索/筛选及原核心管理操作；关闭并重新启动后，数据与组织状态正确保留。
达到后停止扩大范围，整理实测结果、未验证边界及遗留需求，再决定下一 Iteration。
每个 Iteration 须可构建、可运行、可测试、可回退。优先最小修改和复用，不为未来 OCR 建设当前用不到的抽象；保持合理扩展余地。

## 当前执行顺序

1. 保存已有研究、冻结本轮范围；验证：当前分支不含 OCR 脚本、依赖或模型。
2. 修复成品构建/启动的已证实问题，完成迁入及资源包双向过渡验证；验证：针对性测试、源文件校验和与组织信息对照。
3. 制作第一可用版候选 ZIP，验证实际程序的独立库、重启与核心操作，更新 NekoriEmojy 说明；验证：成品运行证据及发布目录隔离检查。
4. 停止扩展，整理结果与遗留项；沿用用户已确认的单次发布前 Final Review 安排。当前中间阶段不等待 DeepSeek，不生成阶段交接包。
