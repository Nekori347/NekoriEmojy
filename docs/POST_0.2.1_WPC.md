## 新反馈的有限结论

### 可见卡片首次输入：#53（关联G-14/#26）

本地隔离真实Gallery卡片新绑定后，在`_is_loaded=False`、未完成Hover／缩略图回调时，以Qt鼠标事件点击，发送入口在约12–18ms收到正确资源身份；稳定后约11–19ms。拖放约38–46ms建立会话，MIME身份正确。发送目标拦截，拖放返回取消；不是实际聊天软件或Windows外部目标验收。

当前有限场景没有复现“必须等视觉完成才接收输入”。点击、拖动路径没有相应门槛；没有为了反馈强行修改成功路径，也不将它直接解释为G-14已解决。保留独立#53，覆盖小隔离库冷卡片及导入增长后的卡片输入，不代表正式用户大库、所有格式或所有启动条件均排除风险。

### 导入期间响应：#54（关联G-25/#46）

在同一隔离库以真实ImportQueue导入180项，定时对真实控件执行点击和Wheel，比较空闲、运行、完成后。卡片发送身份均正确。运行期未捕获多秒阻塞，但完成附近主线程心跳出现约4秒间隔。

局部cProfile确认`_queued_files_finished → refresh_content_incremental → GalleryEntryModel.sync`为变化资源逐项打开SQLite连接，再为新投影项重复按ID查询。180项收尾约4.393s，其中`resource_by_id`361次、目录连接557次。独立提交 **1a81bdb**：`LibraryIndex.resource_records`一次连接沿既有身份规则读取当前变化批次，模型复用已经取得的记录。无全量缓存、全局异步改造、导入操作锁或排序模型变更。

同场景修后回调约0.392s、心跳峰值约4.421→0.415s；180项全部新增，输入身份正确。运行阶段峰值约88→145ms波动，不将其说成运行期全面提升。**收尾仍有约0.4秒短停顿，主要剩余原有路径身份解析，本轮停止扩大优化；#54不是所有正式版导入卡顿均已归因或验收。**

输入测量是Qt事件调用至被拦截发送入口／拖放会话的时间；心跳反映事件循环停顿，不冒称Windows原生输入到屏幕呈现的全链路延迟。专项脚本不使用系统鼠标、不要求用户采样。

证据：`DevData/management-check/WPC-response-profile.log`、`WPC-response-after.log`、`WPC-finish-before.txt`、`WPC-finish-profile.txt`及`WPC-response.json`。保留#53/#54，关联已有Issue而不合并不同验收对象。

帧契约：分类图标是**用户指定时的静态快照**，不是对原资源缩略图元数据的持续订阅。之后修改资源缩略帧，要重新“设为当前分类图标”或在分类图标入口重新选帧；不同帧生成不同图标路径，原有G-07刷新链自然失效旧图。历史GIF图标没有保存过帧信息，不能自动猜回，需重新指定一次。没有新增数据库架构、帧索引缓存或GIF解码器。
