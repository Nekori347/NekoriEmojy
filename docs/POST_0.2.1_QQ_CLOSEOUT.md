## 当前责任链与旧修复核对

- `MainWindow.show_qq_scan()` 复用同一个 QQScanInterface／ToolWindow。共同宿主本轮从 Git HEAD 装入，未启用七处 W-01 实验或 W-03 候选。
- QQDiscovery 在后台读账号／分类，generation 与关闭标记使旧结果作废；发现账号仅读本地昵称缓存，不联网。数字账号目录定位、空结果结束加载及重开复位沿用 dc2179d／79b4d06。
- QQScanWorker 使用现有协作取消；QQPreviewWorker 在后台读／解码／缩放 QImage，GUI 组装小图，沿用 d002233。Marketface/APNG、首项文案及原生批量选择的 49ee000／c45117d 不重做。
- `_set_busy()` 只禁用 QQ 自身按钮与账号／分类控件。没有发现按 QQ 扫描任务统一禁用主窗口的调用，也没有为本轮移除任何任务保护。
- ToolWindow.closeEvent → QQ.shutdown：请求发现／扫描／预览／导出取消、作废旧结果；普通关闭不逐线程 wait。QQ 已交给共享 ImportQueue 的导入继续由队列负责。仅进程 aboutToQuit 的 `_finish_shutdown()` 有总共2秒的收尾预算。
- QQ 日志、导出确认等仍是正常的有界模态交互；不能把正在等待用户确认本身当作残留锁。MainWindow 的已有 Esc 过滤仅作用于其明确条件，本轮没有发现需要替换的事件链。
- `get_display_name()` 仍在确认导出后同步调用 `get_user_nickname()`；远端请求设置 timeout=3。它可造成网络等待期间的暂时停顿，但超时参数不等于严格总耗时上限，更不能据此认定是“返回图库后持续失效”的根因。本轮未改为手动查询或重写导出线程。

## 昵称隐私告知与功能保留

原安全记录“选择／处理账号且缓存过期时查询”过宽。当前实际网络调用仅在 `exportSelected()`／`exportAll()` 确认后，构造导出文件夹名时调用；发现／选择账号使用缓存，扫描和导入不调用网络昵称服务。

最小落地：在**现有使用帮助**追加说明，并在**现有导出确认**的 hint 中于请求前显示相同内容；四语言复用原i18n。没有新增授权弹窗、隐私中心、查询开关或确认步骤。

> 确认导出后，昵称缓存过期或缺失时会向第三方 uapis.cn 发送所选 QQ 号码，用于获取昵称并生成导出文件夹名；结果在本地缓存 24 小时。账号发现、扫描和导入不发起此查询。

保留 `QQExtractor.get_user_nickname()` 的GET查询、24小时缓存、失败回退账号以及昵称目录命名。没有移除本地配置／缓存或改为手动查询。若未来要改变自动／手动或提供禁用选项，应由维护者另行决定；不是本轮的未完成实现。

`tests/test_qq_privacy_notice.py`＋原 `test_qq_lifecycle.py`：**10项通过**。四语言帮助／确认说明、取消前不查询、受控GET只携带测试账号且无图片请求体、缓存命中不重复请求；原发现／取消／预览／Marketface/APNG／选择行为继续通过。模拟网络，不实际查询真实号码。
