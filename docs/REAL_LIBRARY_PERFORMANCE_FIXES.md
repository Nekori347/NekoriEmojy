## 修改与责任层

| 阶段 | 源码提交 | 根因与修正 |
| --- | --- | --- |
| 分类目标菜单 | `24a55c3` | `StorageService.node_choice_rows` 原来沿每个父节点读取混排内容，并被加入/移动菜单各执行一次。改用一次 `Index.nodes()` 有序快照，按真实 parent ID 分组构造路径；两个菜单及懒展开子菜单共享本次 rows/records。无跨菜单缓存。 |
| 导入收尾 | `37f3530` | 稳定 ID 仍进入 `category_labels`；资源变化触发整树及图标投影重建；EntryModel 逐节点查询。稳定 ID 直接使用已有身份表；侧栏按结构/名称/图标及兄弟顺序判断是否需要重建，仅计数变化保留真实树项和已渲染图标；同一 nodes/counts 快照传给 EntryModel。 |
| 渐进呈现 | `45819d0` | 原进度信号只更新任务，图库通常等批次完成或重复决策边界。`ResourceImporter._notify` 在原可靠提交之后通知路径/直接父节点，`ImportThread` 转交；`ImportQueue` 在下一轮 GUI 事件循环合并已到达的变更，图库复用上一阶段的增量更新。目录节点同样在原提交返回后通知。 |

第二阶段的结构变化仍走原建树入口，恢复已有展开、选择和滚动；该次重建暂存旧树项
的 QIcon，仅复用图标未变的项，随后即丢弃暂存表。主动图标编辑仍走原刷新/失效入口，
没有新增永久图标缓存。普通计数更新不调用 `clear`、`select_node`、图标解码或图标视图重排。
G-16 代理绘制没有修改。

EntryModel 继续保留资源记录和原混排投影，只把逐节点 `storage.node()` 改为快照查找。
删除了导入收尾不必要的旧名称解析、完整侧栏投影及重复节点读取，不改变分类身份/归属。

第三阶段没有等待任意固定毫秒，也没有每项全量刷新：同一 GUI 事件轮次已经排队的提交
合并为去重的路径/父节点集合，消费后立即释放，终态前强制排空。慢速大 GIF 本轮通常
一次到达一项，直接做增量更新；快速连续提交可同轮合并。没有新增常驻调度器或持久缓存。
最终 `files_finished`、集中重复决策边界、任务 ID 与最终通知仍保留。
Suzu 自定义 operation 的迁移收尾关系仍沿用最终刷新，不把尚未完成的迁移排序当成最终位置。

T-06 的表结构、事务完成凭据、恢复规划和危险来源边界均未改。新回调在 `_accept` 返回
且存储锁释放之后发生；目录也等原创建事务返回，不提前构造资源。

## 回归与边界

38 个不同定向测试通过（部分在阶段中执行，未重跑全工程）：性能刷新 5、WP-C 图标 5、
G-16/导航展开 6、WP-F/T-06 21、G-17 操作后选择清理 1。覆盖同名不同父级和兄弟顺序、
计数与图标替换、折叠子项身份、目录层级、无缩略图点击、导入中排序、集中 keep/reuse/skip、
失败/取消结果、同任务通知以及隔离进程中断恢复。仅原 QMouseEvent.pos 弃用警告。

经用户授权独占鼠标，Windows 原生滚轮在 51 项/48 GIF 分类验证；缩略图 160px，先确认
存在真实滚动范围，窗口前台且命中卡片，指针保持单一坐标，滚动值 0–180、命中 2 个资源。
每组 6 次 350ms 间隔，上下反向。100ms 预览组实际展示 7 次，心跳 p95/max 16.7/82.7ms；
非卡片组 12.0/20.2ms，1000ms 组 12.3/18.9ms，无多秒阻塞。与前轮 501 项/60px 是不同
布局，仅作为真实 GIF 密集负载回归，不虚构严格 A/B。预览开销仍存在，没有改 QMovie、
指定帧算法或线程数。

仍存在：增量投影/并发排序的百毫秒级尾部；菜单本身及动画能力检查；首次后台去重准备；
大型动图原播放/解码成本；系统压力的进程级因果尚未确定。本轮不继续追逐这些独立热点。
源码改动不改变 W-01 七处实验、W-03 未启用候选、#57、T-07 或原始/正式 Library。
