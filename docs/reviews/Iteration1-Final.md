## 实现与数据边界

- 程序 ZIP 与独立资源库分离；外部图片复制导入；一个库内图片可被多个软件分类、小分类关联。
- SQLite 为运行数据权威；保留原业务库组织，以 ATTACH / DELETE journal 事务统一写入；库相对引用、明确创建/打开、schema 升级备份、会话和维护任务归属。
- Suzu data 在关闭旧版后只读复制与哈希核验；SQLite 只打开检查副本。DB/JSON 差异显式选择，报告缺失/歧义项；原源与原始快照保留。
- 复用普通 Tag、筛选、多选、最近、去重及资源包。v1 只交换旧格式 PNG/GIF、普通 Tag、大分类关系，不是整库备份；小分类/排序/最近/设置不回传。旧基线导入忽略空分类，旧导出可能拆 Tag；直接迁入保持完整文本。
- 小分类平铺、可折叠且随库保存，删除只删除关系；同图不重复存储。
- 当前必要修复为 C# 启动器准确转发 `--library` 参数、Zig `#embed` 每次独立本地缓存避免串用二进制常量。无新增产品运行依赖。

## 已知边界及建议审核重点

请优先找有证据的正确性/数据安全/兼容问题，不做偏好式重构建议：

1. 只读迁入的范围控制、冲突选择、无效引用报告、失败目标不可启用，是否存在影响原源或静默漏组织信息的实际路径。
2. 独立库的 schema / 多 DB 事务、文件操作恢复、任务与会话归属、程序换位置和库复制，是否存在可复现的数据丢失/错库写入路径。
3. 小分类与父分类重命名/删除/移出、共享图片、多选和折叠搜索的关系一致性。
4. 与原资源包 v1 的明确兼容边界。**突然强制结束 exchange 文件复制仍可能留下未登记新文件**，只有普通异常的 DB/文件回滚已证；评估是否应阻挡 RC 试用/正式发布，区分既有数据损坏与新增孤儿文件。
5. 实际 ZIP 的启动器参数、依赖隔离、许可证声明和对应源码。只有 Windows 11 本机验证，尚无干净机器证据；无 objdump，不能把构建脚本返回成功当无 AVX-512 的反汇编证明。
