# G-18 / #39：资源管理栏重构

2026-10-23，分支 `dev/post-0.2.1`，基点 `f005b63`。用户已确认资源批量操作定位和功能结构；此前[事实盘点](MANAGEMENT_FUNCTION_REVIEW.md)保留为设计前依据，其中“待确认”是历史状态。本轮完成实际实现，仍待用户视觉及正常操作验收，不关闭 Issue。

## 实际变化

- `gallery_view.py::_build_command_bar`：左侧计数和文字全选，中部加入分类／移动到分类／编辑标签／调整位置，右侧更多／删除资源／退出。沿用现有 Softframe 控件的平坦绘制、键盘焦点和悬停，50px固定高度；删除独立克制危险色，退出中性。`visual.py::command_bar_style`弱化计数。
- `_layout_selection_actions`：空间不足时依次收纳调整位置、标签、移动、加入；未收纳的动作保持原顺序。所有溢出都在同一个“更多”单层菜单；位置操作直接列首／尾，不再叠一层顺序子菜单。不溢出删除和退出。
- `set_mode`、`_reconcile_selection`、`on_node_clicked`、`_entry_clicked`：进入管理保留资源选择、剔除分类节点及其高光；管理中节点单击不进入资源集合。节点双击导航、展开、右键和拖放路径不变。资源按身份去重；G-20单击不发送、Ctrl/Shift和G-17完成选择清理保留。
- `_sync_command_bar`：全选文字随当前资源投影切换，空结果才禁用；零选管理栏保留，其余资源动作禁用。普通批量状态显示“清除选择”，管理状态显示“退出管理”。缺失资源显示“移除记录”。
- `_batch_assign`、`choose_target_node`、`_assignment_hint`：统一“加入分类”，明确复用资源而非复制文件。移动说明只影响来源分类，其它关系保留；若来源含ROOT，明确相应数量只加入目标分类。纯ROOT依既有规则不提供移动。右键及投放的关系添加同步命名，未改存储事务或模型。
- `_build_selection_more_menu`：固定保留OCR、单项文字编辑、导出、路径、单文件定位、从当前分类移除，沿用ActionPolicy及OCR可用条件。单资源帧、重绑、分类／软件图标继续留在原右键入口。
- `_batch_delete`：保留原确认和删除实现，仅补充影响所有分类关系的范围说明；有效文件／失效记录混合提示保留。与“从当前分类移除”分开。

## 定向验证

21项通过，证据 `DevData/management-check/G18-final-tests.log`。真实Qt控件输入和真实隔离存储，不操作系统鼠标、不向聊天软件发送；仅删除测试夹具中的可恢复文件。

- 管理零／单／多选状态、模式切换及普通点击设置恢复；Ctrl／Shift、多选、单资源专有菜单可用性。
- 展开子分类的重复资源计数仍去重；全选覆盖当前结果，标签过滤及搜索后只选择交集；无结果禁用全选。分类节点原选择在进入管理时清除，管理点击节点不改变资源选择。
- 实际目标选择边界后写入：加入保留源关系，多来源（父／子分类）移动分别移除其来源；ROOT合同仍仅增加目标关系，不删除其它关系。纯ROOT禁用移动，实际目标选择框可见ROOT说明。当前自然投影没有同时呈现ROOT与非ROOT来源的选择，因此该混合分支不宣称已完成自然鼠标场景验收。
- 现有标签对话框全有／部分有状态正确；批量添加新标签后未改的混合标签仍保持差异。
- 实际“移到最后”写入持久顺序；临时显示排序不写入原顺序且禁用位置动作；搜索同样禁用。
- 从当前分类移除后文件、记录和其它分类关系保留；随后混合有效／缺失资源的全局删除确认准确，记录及目标分类关系移除，文件回收。沿用现有Windows删除实现；没有引入新的删除机制。
- 1420／1100／900／760px窗口定向布局：可见控件都在栏内、不相交；菜单单层，动作与溢出一致，选择变化高度不跳动。
- G-17完整成功、取消、失败及部分分组成功；G-21单张／批量／Esc控件取消；G-27外部独立副本；G-04/G-06/G-22拖放与视口；G-14 Hover几何命中；现有显示排序投影相邻回归。
