## 实际发现与处置

| 分级 | 发现 | 处理 |
| --- | --- | --- |
| 必须处理 | 原生包 `package_path`/`icon_asset` 可指向包外；未打包的图片 icon 也可保留本地引用 | 写入前验证全部引用；拒绝绝对路径、父级、Windows 别名/设备路径与符号链接。隔离 PNG 证明修前能被导入，修后拒绝且无入库 |
| 必须处理 | 兼容包 text 图标可被存成图片路径并由后续视图解释 | 跳过路径型/图片型 text 图标，保留正常文本及既有包内图片验证 |
| 建议处理 | 图片 URL 整段 `read()` 无内存上限 | 按 64KiB 写临时文件，声明长度及实际字节均限制 256MiB，失败清理；不转码 GIF/其它图片 |
| 建议处理 | 原生包缺少展开预算 | 最多 50000 条目、8GiB 展开量、16MiB 清单；兼容包只补同等条目/展开预算，原路径/哈希校验保留 |
| 建议处理 | 历史图片 icon 的绝对路径会随原生包清单导出 | 只携带包内 icon_asset，清除清单中原设备路径；图片字节及恢复能力保留 |
| 建议处理 | `data/config.json` 包含本地路径，`.gallery_view.py.swp` 是实际 Vim 交换文件 | 仅停止跟踪并忽略交换文件；本地原文件保留。`config/config.json` 是无路径的 QFluentWidgets 外观配置，未无差别移除 |
| 建议处理 | 默认 Telegram Worker 使用 HTTP，异常可能含 Token/代理认证 URL | 默认改 HTTPS；带凭据请求不自动跟随重定向；Telegram 错误统一脱敏，连接测试不再回显整段代理响应 |

Python `ZipFile.extractall` 对部分非法名称会清洗；本轮没有证明它本身能任意越界写入。
已证明的是 manifest 外部读取及不应接受的歧义成员，两者不混称。
合规资源包仍沿既有资源识别、成员关系、混排排序和事务服务入库，不新增数据库或缓存。
导出时在单次打包内复用共享图标资产，用节点身份命名包内资产，避免同名文件冲突。
旧导出器产生的同名共享图标仍可导入，但必须分块比较字节完全相同；
其它重复成员或内容冲突继续拒绝，不通过允许任意覆盖来兼容旧包。

**尚待维护者决定：**旧 main/标签/历史及已发布源码附件仍保留原配置与交换文件。
当前停止跟踪只能保护未来导出，不能抹去已经公开的内容；本轮不重写历史、不删除或替换附件。

## Telegram 公共默认配置

来源：[Suzu 下载器](https://github.com/IxinorTyan/SuzuEmojy/blob/main/services/tg_downloader.py)、
[Kiowx 页面](https://github.com/Kiowx/tg_sticker_downloader/blob/main/index.html)。
本次分别核对 blob `74d8ad0b777f`、`78ad102cc9cb`；都使用明确 DEF_TOKEN 字面量。
[Kiowx README](https://github.com/Kiowx/tg_sticker_downloader#readme)明确默认内置配置并允许替换。
两者原来都没有在线自动同步。Suzu GPL-3.0、Kiowx MIT 也不构成 Bot/Worker 的长期可用承诺。

1. 自定义 Token 优先；否则读取现有 ConfigService 的公共缓存，没有缓存时使用内置值。
2. 只有官方 HTTPS API 的 HTTP 401 且 Telegram JSON `ok=false,error_code=401` 才启动恢复。
   代理 401、超时、DNS、普通 API 错误、包不存在及 429 均不触发；候选验证遇 429 立即停止。
3. 按 Suzu→Kiowx 顺序读取固定 raw HTTPS 文件；最多 256KiB、有限重定向且只允许同一固定来源集合。
   Python 只读 AST 顶层字面量，JS 只匹配约定 const；不执行源码，结构改变即失败。
4. 候选执行 getMe 验证，成功才提交到现有配置缓存并继续原请求；同一下载器实例最多一次恢复，
   工作线程共享同一锁和结果。不轮询、不增加常驻线程、不建立另一套配置存储。
5. 自定义 Token 不会静默替换，也不再自动交给内置 Worker；明确配置的 CF/本地代理保留，
   包括用户自己填写的 HTTP 地址。原代理字段增加四语言提示；HTTPS 不能阻止代理运营者看到其转发凭据。

有限实网结果：Suzu 当前公开值的官方 getMe 和默认 Worker HTTPS 均成功；Kiowx 官方/Worker 本次超时，
不能认定其 Token 无效。独立应用配置目录中实际跑通旧默认失败→Suzu 候选验证→官方请求成功→缓存，
约 4.14s。只调用公开配置/getMe，没有获取用户资源或发送聊天消息。第三方服务的未来可用性未知。
