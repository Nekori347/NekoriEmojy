## 盘点依据与共同规则

依据实际 GalleryView、ActionPolicy、TagEditorDialog、工作台工具栏及隔离真实控件。主要入口：`fluent_ui/views/gallery_view.py` 的 `set_mode`、`_sync_command_bar`、`on_image_clicked`、`_batch_assign`、`assign_resources`、`_build_selection_more_menu`、`_build_resource_menu`、`_move_selection_extreme`、`_execute_batch_export`；`services/action_policy.py` 决定动作可用性。没有根据按钮名称推定存储语义。

- 管理栏当前顺序：计数、弹性空白、全选、加入分类、移动到分类、标签、顺序、更多、删除、退出。本文不批准这一顺序，也不直接改变它。
- 管理模式零选也显示栏；普通模式选择至少两张资源时也使用这条栏。因此它同时承担管理模式与普通批量操作上下文。
- 资源选择按路径身份去重。同一资源在多分类出现，不是多个独立资源；每个资源另保存一个来源分类。分类卡片也可以在管理模式被选中，但栏的计数和批量动作只面向资源。
- 下表 0/1/N 指选中资源数，不是选中分类卡片数。“当前投影”指当前页面在搜索、过滤、子分类展开条件下的整个资源结果，不仅是屏幕内已渲染卡片。

## 更多菜单、关联入口和边界

- 宽栏的更多包含 OCR、符合条件的移出当前分类、导出、复制路径、单项资源管理器定位；窄栏还接纳被隐藏的加入、移动、标签、顺序。同一省略号兼任空间溢出与次级功能集合，这是当前真实结构，尚未决定最终重组方案。
- 单资源右键另有：动画资源选择缩略图帧、缺失资源重新绑定文件、单项设置当前分类图标（非 ROOT）、设置软件图标。前两者面向资源元数据，后两者分别影响分类和软件配置，不能全归为资源批量操作。管理模式不提供普通模式的右键发送。
- 分类卡片右键主要是打开、展开／折叠内容。左侧分类树另有创建、重命名、图标、文件夹导入、分类导出、删除分类等能力；不能据此声称管理栏已经支持分类批量管理。
- 底部标签面板另有词汇管理、筛选和拖放赋标签等路径，资源“编辑标签”只编辑归属。是否将这些入口整合是产品问题，本轮不合并。
- 资源可单张或批量拖放，沿既有合同完成插入／分类投放；G-21 临时取消区和 Esc 只取消当前拖放，不删除资源、不退出管理模式。G-27 外部交付独立副本的保护保持原样。

## 可以确认的设计问题

1. 可选择分类卡片，但资源计数和操作不承接分类选择；分类节点单独选中时可能显示资源数0。当前事实与“管理模式能管理什么”之间缺少清楚的产品定义。
2. 加入／添加／复制表达同一关系添加；“移动”又受来源关系、ROOT 和多分类归属影响。直接套用文件管理器的复制／移动概念会误导。
3. 当前分类、选择来源分类、整个过滤投影、全局资源与完整持久混排流是不同范围，按钮附近缺少一致的范围说明。
4. 顺序按钮和页头显示排序不属于同一种写入；更多同时承担响应式溢出与常设功能，不同宽度下功能组织变化。
5. 资源标签、标签词汇、OCR 文字分别有不同对象；全局删除和移出分类风险不同，不能只依赖相邻按钮外观区分。

这些是现有组织方式与 Nekori 多分类模型之间可核验的差异。没有逐段核对 Suzu 历史源码，不能把每个问题都归因为特定上游实现；也不以删除继承代码作为设计目标。

以下是已有能力的责任分组，用于确认功能边界，不代表最终按钮位置、排序、入口删减或新建更多菜单：

| 逻辑组 | 已有能力归属 | 待确认部分 |
| --- | --- | --- |
| 模式与选择 | 管理开关、数量、全选／取消、清除、退出 | D1：只管理资源，还是也承接分类节点？后者需要另行定义节点操作，当前不实现 |
| 分类关系 | 加入、移动、移出当前分类 | D2：统一措辞与 ROOT／混合来源说明；保持多分类数据语义，不能暗中改成物理复制或移除全部归属 |
| 资源信息 | 标签归属、OCR、文字编辑、缩略图帧、缺失文件重绑 | D3：哪些是管理栏常用能力，哪些保持右键单项入口？标签词汇管理是否仍独立于此？ |
| 顺序 | 持久移到首尾、拖放插入；显示排序另属浏览范围 | D4：确认对完整来源流的作用范围，特别是过滤、展开子分类和跨来源选择时如何向用户表述 |
| 输出与访问 | 所选文件导出、路径复制、资源管理器定位 | D5：是否属于主要管理任务；先确定常用动作，再决定哪些常驻、哪些保留原入口，不先造新菜单 |
| 破坏性操作 | 全局删除／缺失记录移除；与分类关系移除分开 | D6：风险和对象说明如何呈现；不能改变既有确认或把取消区做成删除区 |

普通模式批量栏与管理模式是否保持相同组织、清除选择与退出是否继续分开显示，也需随结构一起确认。已确认的管理单击不发送、成功后清本次选择、取消失败保留、拖放安全取消均作为保留约束，不重新提交产品取舍。

建议先确认 D1、D2 及日常最常用动作，再确定常驻动作和响应式排列。该建议未被视为批准；确认之前不实施整条栏重构。
